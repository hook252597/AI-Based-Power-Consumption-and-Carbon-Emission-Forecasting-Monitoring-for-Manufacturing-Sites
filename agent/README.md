# 마가렛트 — AI 기반 제조 현장 전력량·탄소 배출량 예측 및 모니터링

제조 현장의 전력 데이터를 학습해 소비량·요금·탄소 배출량을 예측하고,
설비 이상을 감지해 한 화면에서 확인하는 대시보드입니다.
대화형 에이전트가 이상 내역을 설명하고 점검 보고서를 대신 작성합니다.

- 기준 해상도: 1366 × 768 (노트북)
- 설비: 13개 (RTU 채널 1~5, 11~18)
- 데이터 기준일: **2025-05-31 고정**

---

## 파일 구성

이 저장소의 파일은 두 종류입니다.
**AI에게 지시로 넘기는 파일**과 **프로젝트 안에 함께 들어가는 파일**입니다. 섞으면 안 됩니다.

### AI에게 넘기는 지시 파일

| 파일 | 내용 | 쓰는 법 |
|---|---|---|
| `dashBoardPrompt.md` | 대시보드 화면 3개(설비 현황 / 이상현황 / 에이전트)의 전체 명세 | 파일 전체를 복사해 AI 개발 도구에 그대로 붙여넣습니다 |
| `agent.md` | 에이전트 구현 명세 — 도구 함수 11개, function calling 루프, 상태 관리, 오류 처리 | 대시보드가 돌아간 뒤에 넘깁니다 |

두 파일 모두 **파일 자체가 프롬프트**입니다. 머리말이나 설명이 섞여 있지 않으니 통째로 쓰면 됩니다.

### 프로젝트 안에 들어가는 파일

| 파일 | 내용 | 두는 곳 |
|---|---|---|
| `agentSystem.md` | 에이전트의 성격·말투·규칙·대화 예시 | 코드와 같은 폴더. 앱이 읽어서 system 메시지로 넣습니다 |
| `BasicSafetyReportForm.xlsx` | 기본 보고서 양식 (제조현장 안전 점검 보고서) | 코드와 같은 폴더. 앱 시작 시 파싱해 기본 양식으로 등록합니다 |

이 두 파일은 AI에게 지시로 넘기는 게 아니라 **완성된 앱이 실행 중에 읽는 자료**입니다.

## 파일명을 바꾸지 마세요

`agent.md` 안에서 나머지 두 파일을 이름으로 가리킵니다.

- `agentSystem.md` → 에이전트 시스템 프롬프트를 읽어올 파일
- `BasicSafetyReportForm.xlsx` → 기본 양식으로 등록할 파일

이름을 바꾸면 `agent.md`의 해당 줄(12행, 92행, 140행, 169행)도 같이 고쳐야 합니다.

## 작업 순서

1. **예측 모델 학습** — LSTM / XGBoost / Prophet / SARIMA 중 MAE 기준으로 고릅니다.
   이상 탐지는 Isolation Forest 등으로 별도 학습합니다. 이 단계만 "학습"이고, 아래는 전부 조립입니다.
2. **대시보드 제작** — `dashBoardPrompt.md`를 AI에게 넘깁니다.
   한 번에 다 만들라고 하면 뒤쪽 페이지가 성의 없이 나올 수 있으니,
   설비 현황 페이지까지 먼저 확인하고 이상현황·에이전트를 이어 붙이는 쪽을 권합니다.
3. **에이전트 연결** — `agent.md`를 넘깁니다. `agentSystem.md`와 `BasicSafetyReportForm.xlsx`가
   같은 폴더에 있어야 합니다.
4. **검증** — `agent.md` 8번 절의 질문 10개를 돌려봅니다.

## 알아둘 것

**"오늘"은 2025-05-31입니다.**
데이터가 2025년 5월 기준이라, 실제 오늘 날짜를 쓰면 화면이 빕니다.
두 프롬프트 모두 이 날짜를 고정하도록 지시하고 있습니다. 코드에서 임의로 `datetime.now()`로 바꾸지 마세요.

**설비 채널 번호가 띄엄띄엄합니다.**
1~5, 11~18로 중간이 비어 있습니다. RTU 데이터의 컬럼 번호이므로 1~13으로 다시 매기면 데이터와 매칭이 깨집니다.

**임계치는 안전 기준값입니다.**
상전압 210V, 선간전압 360V, 역률 85%. 에이전트가 대화로 바꿀 수 있지만,
기준을 낮추면 이상이 사라진 게 아니라 안 보이게 되는 것입니다.
변경 이력과 되돌리기 기능은 끄지 마세요.

**API 키는 커밋하지 마세요.**
`st.secrets` 또는 환경변수로 읽습니다. 키가 없으면 데모 모드로 떨어지도록 되어 있습니다.

**보고서 양식의 칸 색에 의미가 있습니다.**
`BasicSafetyReportForm.xlsx`에서 연한 청록은 데이터가 자동으로 채우는 칸,
연한 노랑은 사람이 적는 칸, 흰색은 비워두는 칸(문서번호·결재란)입니다.
앱이 이 색을 읽어 항목을 분류하므로 색을 지우지 마세요.

**양식 교체 흐름**
기본 양식이 처음부터 등록되어 있습니다.
첫 보고서를 만들 때 "다른 양식 있으세요?"를 **한 번만** 묻고, 그 답을 파일에 기록해 다시 묻지 않습니다.
사용자가 나중에 "양식 바꿀게"라고 먼저 말하면 그때는 횟수 제한 없이 새 양식을 받습니다.

## 산출물 구조 (예정)

```
margaret/
├─ app.py                        대시보드 진입점 (Streamlit)
├─ agent_tools.py                도구 함수 11개
├─ agent_core.py                 모델 호출과 function calling 루프
├─ agent_ui.py                   에이전트 탭 화면
├─ agentSystem.md                에이전트 시스템 프롬프트 (앱이 읽음)
├─ BasicSafetyReportForm.xlsx    기본 보고서 양식 (앱이 읽음)
├─ report_template.json          현재 양식 (자동 생성)
├─ report_template_default.json  기본 양식 사본 (되돌리기용)
├─ agent_state.json              양식 질문 여부 등 (자동 생성)
├─ models/                       학습된 예측·이상탐지 모델
├─ training-datasets/
└─ may-datasets/
```

아래 세 개(`report_template.json`, `report_template_default.json`, `agent_state.json`)는
앱이 실행 중에 만듭니다. 저장소에 미리 넣지 않아도 됩니다.
