# 이전 검토 이력: AI 점수·지속·반복 알림 후보

이 문서는 2026-10-16에 비교한 **이전 점수·지속·반복 정책**의 이력입니다. 현재 기본 화면은 [센서 확인 정보](SENSOR_INSIGHTS_REVIEW.md)를 사용합니다. 아래 수치와 설명은 당시 정책에만 해당하며 현재 센서 정보 결과와 섞어 인용하지 않습니다. 기존 초안과 테스트의 호환성을 위해 계산 코드·결과를 보존했습니다. 기존 Isolation Forest, 설비별 모델 기준점수와 AI 원기록은 당시에도 변경하지 않았습니다.

## 당시 검토 화면

당시에는 **설비 점검 → AI 알림 후보**에서 비교했습니다. 현재 이 메뉴와 `?view=ai-notifications` 링크는 새 **확인할 정보** 화면으로 연결됩니다. 이 문서를 따라 현재 화면에서 아래 후보 수치가 나올 것으로 기대하면 안 됩니다. 기존 규칙 경고와 AI 원기록은 **전체 탐지 기록**에서 확인합니다.

이 기능은 과거 자료로 알림 정책을 재계산하는 미리보기입니다. 메일·메시지를 실제 발송하지 않습니다.

## 계산 순서

1. 기존 `ai_flag=True`인 모든 5초 표본과 `ai_score`를 읽습니다. 모델을 재학습하거나 다시 추론하지 않습니다.
2. 설비별 기존 모델 기준점수에 점수 여유를 더합니다. 기본 `+0.02`는 점수 차이이며 2% 증가, 전압 변화율, 고장 확률이 아닙니다.
3. 추가 점수 기준을 통과한 표본에서 다음 두 조건 중 하나가 성립하면 후보가 됩니다.
   - **연속:** 같은 원래 AI 구간에서 60초 연속 통과. 점수 미달·정상 표본·관측 누락·날짜 경계에서 이어 세지 않습니다.
   - **반복:** 최근 30분 안에 서로 다른 원래 AI 구간 3개가 추가 점수 조건을 통과. 같은 원래 구간 안에서 점수가 여러 번 오르내려도 반복 수는 1회입니다. 30분 경계는 포함합니다. 관측 누락·날짜 경계에서 반복 이력도 다시 셉니다.
4. 표본의 5초 관측이 끝난 시각부터만 조건을 판단합니다. 연속 60초는 첫 표본 시작+60초, 반복은 세 번째 원구간의 첫 점수 통과 표본 종료 시각에 처음 후보가 됩니다. 미래의 최고점수로 과거 알림을 만들지 않습니다.
5. 같은 설비·연속 관측 범위에서 후보 사이 간격이 10분 미만이면 한 묶음으로 표시합니다. 마지막 후보 후 정확히 10분 이상 떨어진 다음 후보는 새 묶음입니다. **묶음의 첫 시각~마지막 시각은 연속 이상 시간이나 정상 복귀 판정이 아닙니다.**

이전 기본값은 검토용 출발점이며 안전 기준이나 최적 정책으로 검증한 값이 아닙니다. 당시 화면에서는 점수 여유, 연속 시간, 반복 횟수·시간창, 묶음 간격을 바꿔 비교했습니다. 모델 기준점수·원기록은 바뀌지 않습니다. 전압·역률의 고정 기준에서 5%·10%·20% 이탈해야 한다는 필터는 사용하지 않았습니다.

## 기록 보존과 단위

- 원래 AI 표본, 원래 연속 탐지 구간, 조건 충족 후보, 후보 묶음은 서로 다른 단위입니다.
- 원래 AI 구간 = 알림 근거에 포함된 원구간 + 기록만 보관한 원구간입니다. 양쪽은 겹치지 않으며 합계가 원기록 수와 같습니다.
- 반복 판단을 뒷받침한 앞선 구간도 알림 근거에 포함합니다. 나중에 후보 근거가 됐다는 뜻이며, 그 앞선 시각에 알림을 발송했다는 의미가 아닙니다.
- 점수 조건 미달 또는 지속·반복 미달인 구간도 삭제하거나 정상으로 재라벨링하지 않습니다.
- 기존 AI 기록과 새 후보는 CSV로 각각 내려받을 수 있습니다.
- 4월 1~29일의 검증된 5초 캐시만 지원합니다. 다른 기간, 캐시 누락·내용 불일치는 '확인 불가'이며 0건·정상으로 표시하지 않습니다.

## 당시 기본 정책 결과

| 범위 | 원래 AI 구간 | 후보 근거에 포함된 원구간 | 기록만 보관 | 알림 묶음 |
|---|---:|---:|---:|---:|
| 4월 1~29일·전체 설비 | 12,627 | 11,410 | 1,217 | 3,389 |
| 4월 29일·전체 설비 | 459 | 415 | 44 | 128 |

전체 원AI 5초 표본은 12,714개이며 모두 보존했습니다. 실제 연속 탐지 최장은 10초라 기본 60초 지속 조건을 충족한 후보는 없습니다. 기본 알림 후보는 반복 조건에서 발생하며 3호기·예비건조기·6호기에 집중됩니다.

전체 기간 하루 알림 묶음은 99~133개로 여전히 많습니다. 묶어서 표시한 효과와 실제 점검 효용은 다릅니다. 후보 감소를 모델 정밀도·재현율 개선 또는 고장 탐지 성능 개선으로 설명하지 않습니다. 실제 점검 결과와 새 기간 자료를 통한 검증이 남아 있습니다.

## 당시 보고서와 에이전트

- 에이전트의 `get_anomalies`는 원래 AI 구간 수와 `ai_notifications`의 후보 묶음 수를 구분해 반환합니다. 도구 결과를 바탕으로 설명하며 점수를 고장 확률로 말하지 않도록 안내했습니다.
- 보고서의 **AI 탐지 전체 내역**은 원기록을 그대로 포함합니다. **AI 알림 후보** 별첨에 첫 조건 충족 시각, 최초 점수, 후속 포함 최대 점수, 사유·근거 원기록 ID를 따로 담습니다.
- 보고서의 알림 근거·정책은 초안 생성 당시 값으로 고정합니다. 화면 정책을 바꿔도 작성 중 초안이 바뀌지 않으며 새 조건은 새 보고서에서 적용합니다.
- 담당자 종합판정 확인과 기존 입력 보호 절차는 유지됩니다. 실제 GPT API 호출을 통한 신규 대화 검증은 이번에 실행하지 않았습니다.

## 코드와 재현

- `monitoring/ai_notifications.py`: 점수·연속·반복·묶음 계산 및 캐시 검증
- `tools/prepare_ai_notification_cache.py`: 검증된 5초 원본에서 AI 표본만 보존한 휴대용 캐시 생성
- `ui_ai_notifications.py`: 알림 후보와 원기록을 구분하는 화면
- `ml/outputs/agent_data/ai_notification_samples.parquet/.json`: 기존 AI 표본 약 0.6MB와 출처 검증 정보
- `tests/test_ai_notifications.py`, `test_ai_notification_ui.py`, `test_notification_integration.py`: 계산·화면·에이전트·보고서 검증

```powershell
python -m pytest tests -q
python -m streamlit run dashboard_app.py --server.address 127.0.0.1 --server.port 8503
```

기본 캐시가 있으면 원본 대용량 CSV가 필요 없습니다. 다시 만들 경우 기존 `tools/prepare_alert_events.py`와 같은 검증된 `manifest.json`, `daily` 5초 캐시 및 출처 원본이 필요합니다.

```powershell
python tools/prepare_ai_notification_cache.py --source-cache ../outputs/agent_data
```

현재의 팀 검토 순서와 남은 일은 [작업 인계 문서](HANDOFF_2026-10-16.md)를 따릅니다. 이 점수·반복 정책을 현재 기본 운영 알림으로 확정한 것은 아닙니다.
