## 2. 이상 탐지 실험 결과와 결론

실험 코드는 [`../experiments/anomaly_context_v3/`](../experiments/anomaly_context_v3/), 결과 해석은 해당 폴더의 `outputs/decision.json`과 `outputs/context_anomaly_report.html`에 있습니다. 실험 모델 26개(약 34MB)는 비교 결과 보존을 위해 함께 포함했습니다. 원본 대용량 자료, 1분 집계 및 전체 점수·주입 시계열 캐시는 제외하므로 전체 재학습에는 로컬 데이터 준비가 필요합니다. 모델은 운영 대시보드에 연결하지 않았습니다.

실험은 기존 `is_outlier` 라벨과 5월 정답을 사용하지 않았습니다. 12~2월 학습 → 3월 1~15일 경보 기준 조정 → 3월 16~31일 확인 → **4월 개발 재평가** 순서입니다. 이미 여러 번 본 4월을 새로운 최종 검증 자료로 부르지 않습니다.

직전 변화, 이전 5분 평균·변동성, 설비별 평소 수준, 상별 차이, 센서 관계를 추가했습니다. 1분 집계에 공통 3분 연속 조건을 적용하고 비슷한 경보 부담을 목표로 비교했습니다. 이 3분은 실험 조건이며 실제 설비의 안전 기준이 아닙니다.

| 비교 방식 | 인위적 변화 51개 중 탐지 | 대조군에 기존 경보가 없었던 사례의 추가 탐지 |
|---|---:|---:|
| 시점별 센서 정보 Isolation Forest | 42/51 | 40/49 |
| 단순 통계 방식 | 42/51 | 39/48 |
| 시간 변화 정보 추가 Isolation Forest | 27/51 | 26/50 |
| 전압·전류·전력 관계 학습 — 별도 후속 실험 | 41/51 | 40/50 |

- 시점별 IF도 이번에 새로 학습한 비교군입니다. 기존 운영 모델과 동일한 모델의 성능으로 인용하면 안 됩니다.
- 합성 시험은 규칙 범위 안에 변화를 넣어 기능을 확인한 것입니다. 고정 규칙의 탐지 0은 시험 설계에 따른 결과이며 AI의 실제 우월성을 입증하지 않습니다.
- 시간 정보를 추가한 IF가 더 좋지 않았으므로 운영 교체를 보류했습니다.
- 센서 관계 학습은 같은 시점의 일관성 검사입니다. 미래 전력 예측이나 전력의 물리 공식 검증이 아닙니다.
- 관계 방식의 4월 경보는 362구간이지만, 검토용 52개 예시의 최대 잔차는 9.08W, 관측 전력 대비 최대 0.321%였습니다. 이 예시가 모든 경보를 대표하거나 전체 최댓값이라는 뜻은 아닙니다.
- 실제 고장 정답과 현장 확인이 없어 실제 고장 정밀도·재현율 또는 점검 가치는 입증하지 못했습니다. **경보 수를 줄이는 것만으로 개선됐다고 판단하지 않습니다.**

## 3. 다음에 진행할 작업 — 우선순위 순

### 1순위: 탐지 로그와 점검 알림을 분리하는 정책 설계·시험

사용자 제안은 **작은 이상 징후는 로그에 남기고, 변화가 충분히 크며 일정 시간 지속될 때만 알림으로 전환하자**는 것입니다. 아직 구현하지 않았으며, 일괄 ±10%를 최종 기준으로 합의한 상태도 아닙니다.

먼저 다음을 명시한 설정표와 사례를 준비합니다.

1. **10%의 기준:** 설비의 평소 수준인지, 정격값인지, 기존 설정 하한에서 추가 이탈인지 구분합니다. 예를 들어 220V의 10% 하락은 198V지만, 하한 210V에서 추가 10% 하락은 189V입니다. 하한을 중심값처럼 ±10%로 사용하지 않습니다.
2. **항목별 방향·단위:** 저전압·과전압·역률 저하·전력 변화는 따로 판단합니다. 역률 85%에서 상대 10% 하락한 76.5%와 10%p 하락한 75%도 다릅니다. 평소 값이 0에 가까운 항목은 상대 비율만 쓰지 않습니다.
3. **지속 조건:** 같은 설비·항목에서 실제로 이어지는 시간을 사용합니다. 하루의 떨어진 탐지 시간을 합친 누적 시간으로 알림을 발동하지 않습니다. 정상 복귀, 표본 누락, 날짜 경계에서 어떻게 끊거나 이어갈지 정합니다. 누락을 정상 또는 지속으로 간주하지 않습니다.
4. **복귀·재알림:** 경계에서 오가는 상황의 중복 알림을 막고, 관찰 중 → 알림 중 → 복귀 상태를 구분합니다. 복귀 확인 시간, 재알림 간격, 같은 사건을 묶는 기준을 기록합니다.
5. **AI와 규칙의 역할:** AI가 놓친 큰 기준 이탈도 별도의 규칙 경로에서 확인할 수 있게 합니다. 모든 알림을 `AI 탐지 AND 규칙`으로 제한하지 않습니다.
6. **기록 보존:** 기존 라벨·AI 점수·탐지 결과는 유지하고 별도의 `점검 알림 여부`와 사유·정책 버전을 계산합니다. 10% 미만 기록도 검토 가능하게 남깁니다.

비교 후보는 변화 크기 5%·10%, 연속 1분·3분·5분 등으로 두되, 안전 기준으로 소개하지 않습니다. 항목별 적용 가능성을 먼저 확인합니다. 심각한 이탈까지 오래 기다리게 할지 여부는 설비 기준과 담당자의 판단을 받아 별도로 정합니다.

**성공 판단:** 같은 기간에 남은 알림뿐 아니라 제외된 사례도 나란히 검토합니다. 설비·일당 알림 수, 중복 수, 실제 연속 시간, 첫 알림 지연, 알려진 큰 변화의 누락 여부를 함께 기록합니다. 담당자가 확인한 정상/점검 필요 결과와 새 기간 실측 자료가 확보돼야 실제 유용성을 평가할 수 있습니다.

### 2순위: 합의된 알림 정책을 세 화면에 일관되게 적용

정책 비교를 먼저 검토한 뒤 공통 집계 계층에 반영합니다. 대시보드·에이전트·보고서가 같은 건수, 시간, 근거를 사용해야 합니다. 탐지 로그 수와 실제 알림 수를 별도 표시하고, 실측 없음·기준 변경·캐시 부족 상황을 테스트합니다.

**성공 판단:** 5초 단일 표본, 정상 중간 삽입, 누락, 날짜 경계, 복귀 직후 재발, 여러 센서 동시 이탈에서 예상한 사건 수와 알림 시점이 일치해야 합니다. 화면 수치와 보고서 별첨도 일치해야 합니다.

### 3순위: 전체 설비 개요와 예산 화면 조정

**성공 판단:** 처음 보는 사람이 가이드에서 전체 설비를 확인하고, 대상 설비의 근거를 거쳐 보고서 다운로드까지 진행할 수 있어야 합니다. 모바일·어두운 화면에서도 주요 안내와 단위를 확인합니다.

업로드용 복사본에서 대시보드 39개 + 실험 45개, **총 84개 테스트가 통과**했습니다. 관계 실험의 계수·기준 고정 및 시간 순서 검증 3개도 통과했고, 원본 캐시 없이 저장 결과로 HTML 재생성에 성공했습니다. 화면은 PC·모바일 검토를 완료했습니다.

테스트는 5초 구간 의미, 누락·정상 분리, 캐시 검증, 자료 없음, 보고서 초안·세션 분리, 담당자 확인, 전체 별첨, 화면 연결을 다룹니다. 실제 OpenAI API는 호출하지 않습니다.

실험 결과는 HTML 파일을 브라우저에서 열어 검토할 수 있습니다. 전체 실험 재현에는 원본 `rtu_data_full.csv`가 필요합니다. 경로를 자기 PC에 맞춰 명시합니다.

```powershell
python -m pip install -r experiments/anomaly_context_v3/requirements.txt
```

원본에는 약 3,370만 개 5초 표본이 있어 집계에 시간·메모리·디스크 공간이 필요합니다. 새 실험을 시작할 때는 기존 결과를 따로 보관하거나 다른 작업 복사본에서 실행합니다. 원본 전력 단위와 타임스탬프 해석은 제공처 확인이 남아 있으므로 저장된 `outputs/source_data_manifest.json`과 제한 사항을 먼저 읽습니다. 집계를 재생성하면 실행용 `data/manifest.json`이 만들어집니다.
