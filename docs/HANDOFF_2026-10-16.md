## 기본 정책

| 항목 | 조건 |
|---|---|
| 큰 전압 이탈 | 상전압 198V 미만 또는 242V 초과, 1회 관측 |
| 전압 이탈 지속 | 상전압 207V 미만 또는 233V 초과가 60초 연속 |
| 역률 급락 | 70% 미만이고 급락 구간 시작 전 300초 중앙값보다 20%p 이상 하락 |
| 낮은 역률 지속 | 80% 미만이 180초 연속 |

모든 항목은 판단 시점까지 해당 센서 조건 구간 안에 기존 AI 양성 근거가 있어야 합니다. 역률 기준선은 같은 상의 직전 연속 유효 관측으로 구하고 구간 동안 고정합니다. 누락·정상 복귀·날짜 경계에서는 연속 구간을 나눕니다. 원자료가 있는 환경에서는 기준과 시간을 변경할 수 있고, 기본 결과만 포함한 환경에서는 제공 정책으로 검토합니다.

전압은 정격 220V를 가정한 **과제용 시작값**입니다. 설비 정격이나 현장 허용 범위를 확인한 안전·고장 기준이 아닙니다. AI가 놓친 값을 포함한 모든 센서 이탈을 감시하는 독립 안전 경보로 사용하면 안 됩니다.

## 팀원이 먼저 확인할 것

1. 2025-04-29의 전체 13대 카드와 3호기·예비건조기 상세를 확인합니다.
2. “확인할 정보”, “AI 원기록”, “기록만 보관”의 표시 단위를 구분합니다.
3. 동일 날짜·설비로 새 보고서를 만들어 화면과 Excel의 근거·기준이 같은지 확인합니다.
4. 기존 초안 작성 중 화면 대상·기준을 변경해도 초안이 바뀌지 않는지 확인합니다.
5. 원자료 없는 별도 PC에서도 기본 조회가 되고, 지원하지 않는 기준·기간을 0건으로 처리하지 않는지 확인합니다.
6. 설명이 필요한 경우 시작 가이드에서 계산 방법과 자료 범위를 찾을 수 있는지 확인합니다.

4월 29일 기본 결과는 **AI 461표본/459구간, 센서 정보 439구간, 표시 226묶음, 해당 설비 2대**입니다. 구간의 단위가 다르므로 459→226을 감소율이나 성능 개선으로 말하지 않습니다.

## 검증과 재현

원본·개인 설정을 제외한 별도 복사본에서 **172개 테스트 통과**. PC·모바일·어두운 화면 및 기본 캐시만 사용하는 전체 설비→보고서 연결을 확인했습니다.

루트에서 `python -m pytest tests -q`로 계산·화면·에이전트·보고서 회귀 검증을 실행합니다. 테스트는 실제 API를 호출하지 않습니다. UI·집계의 기능 검증 결과와 실제 고장 탐지 성능을 구분하세요.

원본을 준비하거나 캐시를 다시 만들 때만 `tools/prepare_dashboard_cache.py`, `tools/prepare_alert_events.py`, `tools/prepare_ai_notification_cache.py`, `tools/prepare_sensor_insight_cache.py`를 사용합니다. 생성 도구별 입력 요구 사항과 현재 지원 범위는 [검토 보고서](SENSOR_INSIGHTS_REVIEW.md#실행과-자료-범위)에 정리했습니다. 원본·키·사용자 작성 보고서를 Git에 추가하지 않습니다.
